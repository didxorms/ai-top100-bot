# 액션 API 연동 실습

실제 대회 문제와 관계없는 가상 행사 신청으로, 답변만 하는 봇에서 API를 사용하는 봇으로 확장하는 연습입니다.
실제 예약, 결제, 외부 서비스 변경은 발생하지 않습니다.

## 켜는 방법

로컬 `.env`에 아래 값을 설정하고 기존 Python 서버를 종료한 뒤 다시 실행합니다.
학교 서버에서 연습할 때는 같은 값을 관리 화면의 환경변수에 입력하고 재배포합니다.
현재 변경을 GitHub나 학교 서버에 반영하는 작업은 별도입니다.

```dotenv
LLM_MODE=openai
ACTION_MODE=mock
```

```powershell
.\.venv\Scripts\python.exe -m uvicorn bot.app:app --host 127.0.0.1 --port 8000
```

노트북에서 테스트할 때는 기존 터널과 카카오 웹훅 연결도 유지해야 합니다.
모의 API는 봇 프로세스 내부에서 HTTP 요청 형식으로 호출되며 별도 포트를 열거나 서버를 하나 더 실행할 필요가 없습니다.
`app`에 공개 경로로 연결하지 않으므로 외부에서 모의 신청 API를 직접 호출할 수 없습니다.
모의 API 사용료는 없지만 질문 이해와 답변에 사용하는 OpenAI API 비용은 발생합니다.

## 카카오톡에서 확인하기

1. `/실습`을 보내 사용법을 확인합니다. 이 명령은 OpenAI를 호출하지 않습니다.
2. `어떤 행사가 있어?` → 행사 목록과 잔여석을 조회합니다.
3. `EVT001에 2명 신청하고 싶어` → 신청 내용을 준비하고 확인 명령을 표시합니다.
4. 봇이 알려준 `/신청확정 확인코드`를 그대로 보냅니다. 코드 유효 시간은 10분입니다.
5. `내 신청 내역 알려줘` → 현재 요청자 본인의 연습용 신청 내역을 조회합니다.
6. 같은 확인 명령을 다시 보내도 신청이 중복되지 않는지 확인합니다.

처음에는 AI 자동화 체험(EVT001) 10석, 챗봇 제작 실습(EVT002) 2석입니다.
신청당 1~4명을 허용하며, 신청 결과는 같은 서버의 모든 사용자에게 잔여석으로 반영됩니다.
다른 사용자와 동시에 마지막 좌석을 신청해도 서버가 잔여석을 다시 확인해 초과 신청을 막습니다.

`/신청취소`는 아직 확정하지 않은 신청 준비만 취소합니다. 확정된 신청을 취소하는 기능은 없습니다.
`/새대화`는 기존 대화 기억과 현재 요청자의 대기 신청을 초기화하지만 확정된 신청 내역은 삭제하지 않습니다.
그룹방에서는 기존처럼 봇을 멘션합니다. 대화 기억은 방 전체가 공유하고, 신청 소유자는 사용자별로 나뉩니다.
그룹방에 이미 표시된 답변과 대화 문맥은 참가자들이 공유한다는 점은 동일합니다.

## 내부 흐름

```text
카카오 질문 → OpenAI의 도구 호출 요청
           → 서버에서 도구 이름·입력값 검증
           → 모의 HTTP API 조회 또는 신청 준비
           → 도구 결과를 OpenAI에 전달 → 카카오 답장

사용자가 /신청확정 코드를 직접 전송
           → 서버에서 요청자·코드·만료·잔여석 검증
           → 모의 HTTP API로 신청 확정 → 카카오 답장 (OpenAI 호출 없음)
```

OpenAI 공식 함수 호출 문서: https://developers.openai.com/api/docs/guides/function-calling

LLM이 사용할 수 있는 도구는 행사 목록, 행사 상세, 본인 신청 조회, 신청 준비 네 가지입니다.
신청 확정 도구는 LLM에 제공하지 않습니다. 도구 이름, URL, 요청자의 식별 정보도 임의로 바꿀 수 없습니다.
형식에 맞는 입력만 받으며, 프롬프트와 별개로 서버에서 인원·소유자·잔여석을 검증합니다.
한 질문당 최대 네 번의 도구 호출 후 마무리하도록 제한합니다. 전체 답변 생성 제한 시간은 기존처럼 100초입니다.
이 검사는 실행 권한을 제한하는 방어이며, 모델의 모든 부적절한 발화를 차단한다는 보장은 아닙니다.

## 저장과 모드 종료

기존 `conversation-state.sqlite3` 안의 별도 테이블에 요청자 해시, 확인 코드, 행사 ID, 인원, 신청 번호를 저장합니다.
사용자의 실제 카카오 ID와 메시지 원문은 저장하지 않습니다. 기존 SQLite 백업에 실습 신청 정보도 포함됩니다.
서버 재시작 후에도 DB 파일이 남아 있으면 신청 내역과 중복 방지 정보가 유지됩니다.
확정된 연습용 신청은 `/새대화`로 지워지지 않습니다. 새 연습 데이터가 필요하면 별도의 `DATA_DIR`을 지정할 수 있습니다.

기존 대화 봇으로 돌아가려면 `ACTION_MODE=off`로 변경하고 재시작한 뒤 `/새대화`로 실습 문맥을 끊습니다.
실습 모드의 기본값은 `off`입니다. `.env`에 직접 설정하기 전까지 기존 봇처럼 동작합니다.

## 대회 당일 교체할 부분

- `bot/action_tools.py`: 실제 문제에 맞는 도구 설명·입력 형식·사용 절차로 변경합니다.
- `PracticeActions.request`: 운영진이 제공한 실제 API의 고정 주소·인증·요청 형식에 맞는 클라이언트로 교체합니다.
- `bot/practice_api.py`: 모의 행사와 신청 로직을 실제 API의 결과 및 규칙으로 교체합니다.
- 현재의 확인 명령은 연습용 설계입니다. 실제 문제의 실행·확인 요건을 읽고 필요한 동작으로 조정합니다.
- 인증 키와 사용자 식별 정보는 서버에서 전달하고 모델이 직접 정하도록 하지 않습니다.
- 타임아웃, 잘못된 입력, 권한 없는 접근, 중복 실행을 실제 명세 기준으로 검증합니다.

이 모의 구현만으로 운영진 액션 서버 연동 요건을 충족한 것은 아닙니다.
최종 제출 전에 실습 모드를 실제 구현으로 교체하고 검증한 버전을 고정합니다.
제출 후에는 코드, 프롬프트, 환경변수, 배포 설정을 변경하지 않습니다.
